# Git 常用命令速查手册

## 核心操作命令速查

| 操作场景 | 命令 | 说明 |
| :--- | :--- | :--- |
| **获取代码** | `git clone <仓库地址>` | 首次将远程仓库完整下载到本地。 |
| **查看状态** | `git status` | **高频命令**。随时查看哪些文件被修改、新增或删除，以及它们所处的状态。 |
| **分支操作** | `git branch` | 列出所有本地分支，当前分支前会有 `*` 号。 |
| | `git branch <新分支名>` | 创建一个新分支，但不会自动切换过去。 |
| | `git checkout -b <新分支名>` | **常用**。创建新分支并立即切换到该分支。 |
| | `git switch -c <新分支名>` | Git 2.23+ 版本提供的新命令，功能同上，语义更清晰。 |
| | `git checkout <分支名>` | 切换到指定的已有分支。 |
| | `git switch <分支名>` | Git 2.23+ 版本提供的新命令，功能同上。 |
| | `git branch -d <分支名>` | 删除一个本地分支（需确保分支已合并）。 |
| **暂存与提交** | `git add <文件名>` | 将指定的文件添加到“暂存区”，准备提交。 |
| | `git add .` | **常用**。将当前目录下所有**已跟踪文件的改动**添加到暂存区。 |
| | `git add -A` | 添加所有改动，包括新文件和被删除的文件，比 `git add .` 更彻底。 |
| | `git commit -m "提交信息"` | **常用**。将暂存区的改动正式提交，并附上一条清晰的描述。 |
| | `git commit -am "提交信息"` | **快捷方式**。跳过 `git add`，直接提交所有已跟踪文件的改动（对新文件无效）。 |
| **同步代码** | `git pull` | **常用**。从远程仓库拉取最新代码并自动合并到当前分支（相当于 `git fetch` + `git merge`）。 |
| | `git pull origin <分支名>` | 拉取并合并指定远程分支的代码。 |
| | `git push` | **常用**。将本地当前分支的提交推送到远程仓库的同名分支。 |
| | `git push origin <分支名>` | 将本地当前分支推送到远程的指定分支。 |
| | `git push -u origin <新分支名>` | 首次推送一个新分支，并将本地的该分支与远程分支关联起来，之后再用 `git push` 即可。 |
| **查看历史** | `git log` | 显示当前分支的提交历史。 |
| | `git log --oneline --graph` | **常用**。以简洁的一行格式和图形化的方式显示分支历史，结构一目了然。 |
| **撤销与修改** | `git diff` | 查看工作区中尚未暂存的改动内容。 |
| | `git diff --staged` | 查看已暂存但尚未提交的改动内容。 |
| | `git reset HEAD <文件名>` | 将文件从暂存区撤回，但保留工作区的修改。 |
| | `git checkout -- <文件名>` | **危险**。放弃工作区对指定文件的所有修改，恢复到上一次提交的状态（不可恢复）。 |
| | `git restore <文件名>` | Git 2.23+ 版本的新命令，功能同上，更安全。 |
| | `git commit --amend` | 修改最近一次提交的提交信息或内容，不会产生新的提交记录。 |

## 特别技巧与场景

### 如果代码冲突了怎么办？

执行 `git pull` 时，如果提示有冲突（Conflict），不要慌张。

1. 用 `git status` 查看哪些文件冲突了。
2. 打开这些文件，Git 会用 `<<<<<<<`、`=======`、`>>>>>>>` 标记出冲突区域，手动编辑选择保留哪部分代码。
3. 删掉所有标记符号，保存文件。
4. 重新执行 `git add .` 和 `git commit -m "解决了合并冲突"`，完成一次合并提交。

### 想“悔棋”但又不想完全丢掉改动？

用 `git stash` 可以把当前未提交的改动暂存起来，让工作区变干净。之后用 `git stash pop` 可以恢复这些改动。这在你想临时切换分支时非常有用。

### 刚刚提交完，发现信息写错了？

- 用 `git commit --amend -m "新的提交信息"`，可以修改最近一次提交的说明文字。
- 如果漏掉了一个文件没提交，可以 `git add` 那个文件，然后 `git commit --amend`，就能把文件合并到上一次提交里。
